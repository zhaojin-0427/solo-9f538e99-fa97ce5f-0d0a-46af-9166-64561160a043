# 广播剧混音审听台

声音导演交片前的逐段审听工具：上传同一集的两条轨，按采样编号设置/清除静音，
两轨相加限幅到 16 位后按 5 秒一段逐段试听、确认，全部通过后方可下载整集 WAV。

## 快速开始

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

### 本地运行

```bash
pip install -r app/requirements.txt
python3 app/app.py          # 监听 0.0.0.0:8000，可用 PORT 环境变量修改
```

打开页面后点 **载入内置样例** 即可立即试听（27 秒、44.1 kHz、6 段；
第 3 段 10–11 秒处两轨同相叠加，可听到限幅效果）。样例也可直接播放：
`samples/sample_a.wav`、`samples/sample_b.wav`（由 `samples/make_samples.py` 生成）。

## 使用流程

1. **上传**同一集的两条轨（轨 A / 轨 B）：必须是 16 位单声道 PCM WAV，
   等长、同采样率，否则整体拒绝。
2. **静音编辑**：按采样编号为每轨维护若干半开区间 `[起, 止)`，可添加/删除/
   清除，点 **保存静音改动** 一次性原子保存两轨。
3. **逐段审听**：混音每 5 秒一段（末段可不足 5 秒）。每段先 **▶ 试听**
   再 **✔ 确认通过**；确认时服务端校验"刚试听的混音"与该段当前内容一致
   （SHA-256 哈希），不一致则拒绝并要求重新试听。
4. **下载整集**：全部段落通过后才可下载整集 WAV。

## 关键设计

- **通过状态由内容哈希驱动**：每段保存"曾被确认通过的混音哈希集合"，
  当前混音哈希 ∈ 集合即视为已通过。因此：
  - 保存静音后，**只有混音样本值实际变化的段**需要重听（哈希未变的段自动保持通过）；
  - 静音改回旧内容（如取消静音）时，若该内容此前已确认过，**自动恢复通过**，无需重听；
  - 集合中每个哈希都来自一次真实试听确认，不会放过未听过的内容。
- **保存原子性**：静音区间先全部校验、先在锁外算好全部新哈希，再一次性换入；
  任一区间非法 → 整体 400，**原混音与通过状态不变**。
- **下载快照**：开始下载时（须全部通过）即快照轨道引用与静音表，之后流式生成。
  下载进行中他处改音/重传，**本次下载继续交付当时通过的混音**。
- **单段缓冲**：下载按段生成、逐段发送，应用层内存中最多暂存一段待发送的
  混音 PCM（源轨 PCM 整体常驻内存，这是混音的数据来源，非"待发送缓冲"）。
- **停读不阻塞**：流式生成器不持有全局锁；多线程 WSGI（waitress / Flask
  threaded）下，浏览器停读或断连只占用该下载自身线程，其他窗口的保存、
  试听、确认不受影响。
- **跨窗口共享**：状态保存在服务端单例中，所有窗口看到同一份审听进度；
  前端每 2 秒轮询同步他处改动（他处保存静音后本端段落状态自动刷新；
  本地正在编辑静音面板时给出提示而不覆盖输入）。

## API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 审听页面 |
| POST | `/api/upload` | 上传 `track_a` / `track_b` 两个 WAV（multipart） |
| POST | `/api/load_sample` | 载入内置样例 |
| GET | `/api/state` | 剧集信息、各段状态、静音表、版本号 |
| POST | `/api/mutes` | 保存静音 `{"A": [[s,e],...], "B": [...]}`（缺省轨保持原样）；返回失效段列表 |
| GET | `/api/segment/<i>.wav` | 第 i 段混音 WAV，响应头 `X-Mix-Hash` 为该段混音哈希 |
| POST | `/api/confirm/<i>` | 确认通过，请求体 `{"hash": 试听时拿到的哈希}` |
| GET | `/api/download` | 全部通过后才可下载整集 WAV（流式） |
